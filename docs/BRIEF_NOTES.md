# Notes on MVP_BRIEF.md (2026-11-02)

From a six-lens review of the brief against the gate prep and the Meta API facts, each finding checked by independent skeptics. These are for the brief's author; none of them changes the gate. "Assume if silent" is what the Monday build will do unless you decide otherwise.

1. **Section 7's failure policy does not match the API's failure modes** (lines 126 and 191). Constrained decoding makes a shape-validation failure the unlikely case. The documented failures are a `status` other than `completed` when reasoning plus output hit `max_output_tokens`, 429/500/502/503 with `Retry-After`, and 504, which must not be retried. "Valid brick" in criterion 1 (line 180) is undefined. Assume if silent: valid means `completed` and parsed; on the cap, re-call once at 16,000 output tokens; retry 429 and 5xx up to twice honouring `Retry-After`; never retry 504; zod is a guard, not the expected failure; a dangling `source_hypothesis` makes the relation `interpreted`, a dangling `rests_on` id drops out of the chain; an off-vocabulary `target` lands in `unexpressed` with reason `unsupported_target`, as line 97 already says.
2. **`/api/extract` has no downscale** (line 146). Every number the gate produces is measured on an EXIF-upright image downscaled to the sealed long side and re-encoded as JPEG. Assume if silent: the browser makes the photo upright and downsizes it to the same long side on a canvas, then POSTs base64. A raw phone photo as base64 exceeds Vercel's 4.5 MB request body cap, costs several times the image tokens (the harness estimate, unverified above 1280 px), and leaves it to Spark whether the 0-1000 grid is rotated. `photo.width` and `photo.height` are the sent dimensions.
3. **The collection before any project has no type and no persistence** (sections 4, 5, 10). Section 10 persists only "the current composition"; `Composition` embeds `bricks` and requires `intent`; `Brick` has no saved date and no sealed note, both of which the demo's first 20 seconds show. Assume if silent: two localStorage stores, `collection` (Brick[]) and `composition` (intent, brick ids, relation state, parameters); `Composition.bricks` becomes `brickIds: string[]`, matching `ParameterValue.source.brickId` and `unexpressed[].brickId`, which already reference bricks by id; `Brick` gains `saved_at` (the save time, hand-set for the three fixtures to spread the dates) and `why_saved` (the sealed note), both set by the client and never requested from Spark. Decide: whether a collection screen exists before the intent prompt. Section 10 has no gallery view and section 11 has no slot for one.
4. **`Relation` has no `id`** (line 56), while `unexpressed` and `ParameterValue.source` reference relations by rule string. `brick.json` and the stand-in prompt give relations `r1, r2, ...`. Add `id: string` to the type, or drop it from `brick.json` when mirroring your schema.
5. **Section 4 versus section 5 on mapping.** Line 49 says mapping to parameters happens only inside a project; line 56 puts `parameter` and `target` on `Relation`, and line 146 returns a `Brick` straight from Spark. The build assumes the shell's parameter vocabulary is fixed and product-agnostic, so the model proposes `parameter` and `target` at extraction time and a project chooses which brick sets which key. Reword line 49 to say that, or decide the other way before the prompt is final.
6. **Smaller items.** `rest_on` on line 96 should read `rests_on`. The font rule on line 135 reads its confidence from the `type_family` relation's source hypothesis; say so in section 5. Normalize `target` strings in `mapRelations.ts` (case, units, `<=` versus `≤`) rather than rejecting them, and let zod swap a box whose corners come back reversed instead of rejecting the brick. Criterion 7's side-by-side needs no Spark call: run the general agent after a pass with the exact prompt sealed in `gate_notes.md`, and decide whether it gets `content.json`. Name the detail screen's fallback if grouping and rhythm are cut per section 11. "About 30 calls, under $1" holds at typical output; at the 12,000-token cap, 30 calls are about $1.70.
